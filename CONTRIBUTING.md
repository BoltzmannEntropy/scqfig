# Contributing to scqfig

scqfig draws the figures a superconducting-qubit or chip paper needs, in two styles that a user
switches with one call. Every plot type ships with a plot function, a demo in `examples/`, and a
place in the gallery. These conventions keep the two styles consistent and the physics honest.

## Layout

| Path | Holds |
|---|---|
| `src/scqfig/themes.py` | the palette and the two Theme objects (single source of truth) |
| `src/scqfig/core.py` | `use`, `style`, `figure`, `save`, `panel`, the marker grammar, `note`, `pm` |
| `src/scqfig/physics.py` | exact models: transmon, SQUID, dispersive, Purcell, notch S21, TLS, Wigner, Bloch, RB |
| `src/scqfig/fit.py` | fits returning a `Fit` (callable, indexable, `.errors`, `.derived`) |
| `src/scqfig/plots/<family>.py` | plot functions, one module per family |
| `src/scqfig/plots/_base.py` | `heatmap`, `annotated_matrix`, `colorbar` |
| `src/scqfig/schematics/` | circuit symbols, chip motifs, chip plan view, wiring, pulse sequences |
| `src/scqfig/schematics/qcircuit.py` | `QCircuit`: gate-model circuits with column packing, slices, meters and classical wires; its quantikz twin is `scqfig circuit` in `latex.py` |
| `src/scqfig/check.py` | the colour-rule checker run on every example |
| `examples/NN_name.py` | one demo per plot type; `build_gallery.py` renders them all |
| `latex/scqfig.sty` | generated by `python -m scqfig.latex`; never edit by hand |

## A plot function

```python
def ramsey(ax, t, p, *, err=None, fit=True, unit="µs", loc="upper right"):
    """One-line summary in plain words. Then what is drawn and what is returned."""
```

1. Take the `ax` to draw on and the data arrays first. Options are keyword-only.
2. Take every colour from `theme()` at call time: `t = theme()`, then `t.data`, `t.model`,
   `t.accent`, `t.levels[m]`, `t.qubits[k]`, `t.chip["flux"]`. Never write a hex literal. Use "white"
   only for text on dark cells and for open-marker fills.
3. Use the marker grammar:
   - measured points `data_kw()`, filled in field and open in folio;
   - simulated or designed values `sim_kw()`;
   - values from another source `assumed_kw()`;
   - fit and theory curves `model_kw()`;
   - guide lines `ref_kw()`;
   - several series `series(i)`, which gives the colour, line style and marker of series i.
4. Pass `ls=` on every `ax.plot` that is not built from the helpers above. In folio, series differ by
   line style, so a line with no explicit style should not depend on the cycle.
5. Draw heatmaps with `_base.heatmap`, matrices with `_base.annotated_matrix`, and colour bars with
   `_base.colorbar`. Over a heatmap, draw model lines in `t.overlay`.
6. Print a fitted value with `note(ax, rf"$T_2^*$ = {pm(v, e, 'µs')}")`.
7. Return what a user needs next: the `Fit`, the mesh and colour bar, or a dict of artists.
8. Add the name to the module's `__all__`.

## Physics is computed, never sketched

Wavefunctions, levels, spectra, chevrons, Wigner functions and response curves come from
`scqfig.physics` or from a model inside the function. A new model goes into its own module or the
plot module with a docstring, units and a test. Schematics stay truthful too:
- a chip is a rigid drawing laid on the page by one affine map (`motifs.onto_plane`);
- a field quantity is a colour wash or a separate plot, never a bent chip;
- a drive is a wavy arrow, never a displaced element.

## Colour rule

Every colour is one of blue `#1f5fbf`, magenta `#c2378f`, purple `#5e2a84` or orange `#e69f00`, a
tint of one of them (`lighten(hue, f)`), or a grey. Never use green, red, cyan, teal, brown, ochre or
vermillion. `check.violations(fig)` lists offenders, and the example test fails on any of them.

```python
    sq.demo_main(build, __file__)
```

- **Docstring:** the first line becomes the gallery caption. Say "(synthetic data)" when the data
  are generated.
- **Data:** seed every random generator. Draw realistic numbers from the models in `physics`.
- **Size:** use `sq.figure("column", ...)` (3.4 in) or `sq.figure("page", ...)` (7.0 in). Figures
  are drawn at print size, so they go into LaTeX without scaling.
- **Numbering:** `0x` spectrum, `1x` design, `2x` readout, `3x` time domain, `4x` states, `5x`
  noise and errors, `6x` processor, `7x` and `8x` schematics.

## Checking your work

```bash
PYTHONPATH=src python -m pytest -q
python examples/build_gallery.py --only 31
```

- **Tests:** `tests/test_examples.py` builds every example in both styles. It fails on missing
  glyphs, collapsed layouts and colour-rule violations.
- **Look at the renders:** open both `gallery/field/NN_name.png` and `gallery/folio/NN_name.png`.
  Check for text overlapping lines, labels running outside the frame, crowded ticks, and legends
  covering data.

## Prose

Write docstrings and captions in plain, active sentences. Avoid em dashes and colons used for
rhetorical effect.
